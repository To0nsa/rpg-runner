# Swimmable water delivery validation

September 13, 2026. Feature commit: `c062ad40`.

## Delivered

The [strategy](swimmable_water_strategy.md) and
[checklist](swimmable_water_implementation_checklist.md) are complete.
The feature includes strict water rectangles, atomic runtime publication,
deterministic swimming, animated atlas materials, foreground water rendering,
editor creation/edit/delete and frame authoring, captured Play, and a Field
example. Instructions are in the [gameplay guide](../../gdd/swimming.md);
contracts are in the [TDD](../../tdd/swimmable_water.md).

## Passing evidence

Checks used the installed Flutter/Dart SDK and cached package resolutions.

- Analysis: Core, content pipeline, terrain materials, game, generator, editor
  and replay validator report no issues.
- Content pipeline: 49 tests passed. The final example additionally passed
  source generation, atomic water binding, repeatable swimming, floor contact,
  and a stroke-assisted exit over its solid bank.
- Terrain materials: all 25 tests passed, including frame timing at 30/60/120 Hz,
  pause, strict source validation, traversal and later-frame PNG bounds.
- Rendering: 11 terrain/atlas tests passed. The real-atlas raster check verifies
  animation changes, continuous world phase across adjacent pools, clipping,
  readable submerged actors, and cached-image disposal. The rendered preview
  was inspected visually.
- Editor: pool modal validation, typed plugin edits, stale/no-op rejection,
  revision behavior, Save diffs and copy preservation passed. Captured background
  Play preserves water signatures and all animation assets, and its Core enters
  swimming. Material-page and scene/default-selection regressions were corrected
  and passed focused checks. Preparation performance passed on its focused rerun.
- Replay validator: all 103 tests passed, including replay/direct-Core swimming
  equality and simultaneous jump/dash input without suppressing the stroke.
- Generated content: an isolated copy of tracked authoring sources plus the
  example validated 27 chunks, generated all outputs and passed a clean dry-run.
  The committed material registry exactly matches that generator output.

## Existing repository failures

Broad suites were also run; they are not entirely green. The same remaining
failures were reproduced using isolated original code from before this feature:

- Core: 409 passed, four failed. These concern the generated catalog polygon
  count, Forest long-run survival, registered whole-level parity after run end,
  and a fixture's missing `rocky_grove` section pool.
- App Core/game/Play selection: 376 passed, six Play-host tests failed while
  waiting for `ready`. Original-code runs reproduced all six loading timeouts.
- Editor: the remaining new-level preparation fixture and accepted-Play
  projection fixture also fail in the original editor. The initial full run
  had 761 passes and two skips; five failures involving new material/default
  selection or the water fixture were subsequently fixed, and its performance
  timeout passed when rerun without full-suite contention.

The root generator dry-run validates 26 saved chunks but reports three stale
outputs: `level_registry.dart`, `authored_chunk_patterns.dart`, and
`staged_authored_terrain.dart`. The existing runtime contains 22 chunks, including
older Forest content. This feature preserves those original generated bytes
instead of activating unrelated level edits. Water is an optional extension of
staged format 4; dry chunks require no format migration or generated changes.
The water material is generated normally. A future root Build will also publish
the currently saved level-source changes.

Existing edits to `prefab_defs.json` and `tile_defs.json` were excluded from the
feature commit. The example remains under docs until an author chooses to add it
to a level's source directory.
