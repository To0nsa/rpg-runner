This checklist implements Phase 1 only: extract the repository-independent
current-schema runtime content pipeline into a pure-Dart package, adapt the
root generator to that package, and expose a typed single-chunk boundary for
later editor playtest preparation without changing generated bytes, signatures,
Core authority, or editor behavior.

## Completion gate

Phase 1 is complete only when:

- `packages/runner_content_pipeline` is the single owner of strict Prefab-v3
  and Chunk-v2 terrain decoding, compilation, seam validation, staged-terrain
  materialization/rendering, and runtime `ChunkPattern` materialization
- the package depends on `runner_core`, while `runner_core` has no reverse
  dependency and no Flutter, Flame, editor, filesystem, or CLI dependency
- repository filesystem reads/writes, fixed target paths, process exit codes,
  and generated-artifact drift/write orchestration remain under `tool/`
- the repository generator consumes the shared package for the complete
  current-schema terrain and runtime chunk products
- a caller can compile one canonical Chunk plus Prefab/tile source strings into
  typed `ChunkPattern`, `StagedTerrainChunkData`, and canonical issues without
  repository I/O
- all existing generated Dart bytes and every reviewed terrain signature remain
  unchanged
- root generator, package, Core, and focused editor parity tests pass, subject
  only to the already accepted Phase 0 external baseline exceptions

## Scope boundaries

### In scope

- new pure-Dart `runner_content_pipeline` package, public barrel, guidance, and
  package tests
- moving pure polygon source, compilation, seam, and rendering ownership out of
  `tool/`
- decoupling repository generation from root `LevelDefinitionSource` through a
  small typed scheduler-level input contract
- typed in-memory materialization of staged terrain and runtime chunk pattern
  data
- root generator adapters for file I/O, level conversion, artifact planning,
  and deterministic Dart rendering
- root and editor path dependencies on the shared package
- import migration and deletion of superseded root-only pure modules
- byte/signature/parity characterization required to prove the move
- Phase 1 documentation and package-boundary updates

### Out of scope

- `GameCore.chunkPlaytest`, staged-terrain override/catalog behavior, or any
  production Core constructor change
- editor scenario preparation, Play UI, or editor imports of package APIs
  beyond declaring the dependency for the later scenario builder
- semantic action dispatcher or keyboard/mouse listeners
- backend, replay, run protocol, rewards, leaderboard, or Firebase changes
- generated schema or authoring JSON changes
- relaxing strict Prefab-v3/Chunk-v2 validation or adding compatibility readers
- manual terrain-material work or fixing the accepted unrelated editor test
  failure

## Chosen ownership split

| Concern | Phase 1 owner |
| --- | --- |
| Strict Prefab-v3/Chunk-v2 string decoding | `runner_content_pipeline` |
| Core terrain compilation and signatures | `runner_content_pipeline` calling `runner_core` |
| Scheduler reachability and compiled seam validation | `runner_content_pipeline` calling `runner_core` |
| Typed staged-terrain materialization | `runner_content_pipeline` |
| Deterministic staged-terrain Dart rendering | `runner_content_pipeline` |
| Typed visual sprite/spawn marker `ChunkPattern` materialization | `runner_content_pipeline` |
| Single-chunk compile result and canonical issues | `runner_content_pipeline` |
| Level JSON loading and generated level Dart | root `tool/` |
| Repository directory traversal and source reads | root `tool/` |
| Fixed generated target paths and drift/write plan | root `tool/` |
| CLI arguments, logging, and exit codes | root `tool/` |

No compatibility export shims remain in `tool/`; all consumers migrate to the
package in the same phase.
