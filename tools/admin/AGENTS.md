# Admin tool

Read the [operator guide](README.md), [architecture](../../docs/tdd/admin_tools.md)
and [inbox contract](../../docs/tdd/system_inbox.md).

- Own the Flutter Windows operator app and its Node local service. Reuse
  [tool UI](../../packages/tool_ui/AGENTS.md) and
  [game presentation](../../packages/game_presentation/AGENTS.md); keep editor
  authoring sessions and gameplay authority outside Admin.
- Require explicit registered environments. Never infer project from ADC/gcloud.
  Preserve the existing dedicated credential path and child-only identity
  overrides. Do not change shared ADC or expose credentials/session tokens.
- Keep previews immutable, sends preview-ID-only, and drafts durable before send.
  Preserve delivery identity on uncertain results, restart and import. A failure
  must not imply delivery; confirm only a matching receipt. Fence stale catalogs.
- Use `functions/src/inbox/operator.ts` for real sends and store ownership grants
  for claims. Follow [backend rules](../../functions/AGENTS.md) for those changes.
  No direct UI ownership writes or arbitrary IDs/quantities.
- Missing rollout configuration fails closed for new item/skill gifts. Never
  enable the gate or send real gifts merely to test. Local implementation is not
  deployment authorization. Use fixture mode and demo-project emulator tests.
- `tools/admin` belongs to the root Pub workspace; no member lockfile. Windows
  scaffolding is app source; build output and drafts are not source. The app is
  repository-backed, not a packaged standalone installer.
- `test/fixtures/catalog.json` is generated by `service/catalog.mjs` from compiled
  Functions. Build Functions, regenerate/check it, then run the Dart consumer test.
- Validate service changes from the root with `corepack pnpm admin:test:service`;
  Flutter changes with `flutter test` and targeted analysis from this directory.
  Build Windows when changing native startup/plugins. Shared changes follow
  [shared tool changes](../../.agent/workflows/change-shared-tools.md).
